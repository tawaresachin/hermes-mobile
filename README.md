# Hermes Mobile

Android companion app for [Hermes Agent](https://hermes-agent.nousresearch.com) — chat with your
agent, drive it from anywhere, and manage the server itself from your phone.

Connects **directly to the gateway (port 8642)** over LAN, Tailscale, or any tunnel. No bridge,
no relay: the app speaks the same HTTP/SSE API Hermes Agent Desktop exposes. Pairing is one QR
scan (generated by the [hermes-mobile-plugin](https://github.com/tawaresachin/hermes-mobile-plugin)
on the server) — URL, API key, and connection test are configured automatically.

## Features

- **Chat** — streaming replies, Markdown + code highlighting, model picker (dynamic from server,
  zero hardcoded models), slash commands (`/new` `/stop` `/model` …), retry, share
- **Files** — send attachments; in-chat previews for images, PDF, Office docs, JSON/code with a
  guarded fallback + external open; download to device
- **Voice** — press-to-talk, Whisper STT + TTS reply playback, full-duplex mode
- **Sessions** — list/search/switch sessions created by any platform (Telegram, CLI, Desktop);
  swipe actions; server is the source of truth for usage/context
- **Settings** — connection card (URL/key/test/QR), chat text size, Token Optimizer, auto-approve,
  keep-awake, dark theme; About row shows server version + update check

## Requirements

- Hermes Agent with `hermes-mobile-plugin` installed and the gateway running (api_server on 8642)
- Android 8.0+ (minSdk 26); phone and server reachable over the network (Tailscale recommended
  for cross-network use)

## Install

Grab the latest `Hermes-Mobile-vX.Y.Z.apk` from
[Releases](https://github.com/tawaresachin/hermes-mobile/releases), install, scan the QR from
`hermes-mobile-qr` plugin output (`~/.hermes/qr/connection.html` or `python -m
hermes_mobile_plugin.cli generate-qr`), done.

## Build from source

```bash
./gradlew :app:assembleDebug          # APK: app/build/outputs/apk/debug/
./gradlew :app:testDebugUnitTest      # 62 JVM tests
```

Toolchain: JDK 17+, Android SDK 35, Kotlin/Compose (Material 3). No hardcoded endpoints or models.

## Versioning & releases

App and plugin are **separate products with independent versions**.
[`scripts/release.sh`](scripts/release.sh) is the only sanctioned bump path — it sets
`versionName` + derived `versionCode`, commits, tags `vX.Y.Z` on both repos as applicable,
pushes, syncs the deployed plugin copy, and verifies the contract
(`scripts/check_versions.sh`, also wired as a pre-commit hook in both repos).

```bash
./scripts/release.sh 0.0.48              # app only
./scripts/release.sh none 0.0.7          # plugin only
```

## Diagnostics

Crash dumps are stored on-device and auto-uploaded to the server on next launch
(`~/.hermes/mobile-logs/diag/`). Settings → About → **Share logs** ships the current buffer.
